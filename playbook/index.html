Power Pages UI Framework

A centralized, CDN-hosted UI framework for building consistent, scalable, and enterprise-ready user interfaces across Power Pages. This playbook is the single source of truth for components, governance, and integration standards.

Why use this framework?

Building user interfaces in Power Pages often leads to duplicated code, inconsistent styling, CSP violations, and high maintenance effort across portals. Each project ends up solving the same UI problems repeatedly.

This Power Pages UI Framework exists to solve those challenges by providing a centralized, reusable, and enterprise-ready UI system that works seamlessly with Power Pages security and governance models.

Instead of rebuilding UI logic for every portal, teams use a single CDN-hosted framework that standardizes components, behavior, and visual design across the organization.

Key Advantages

  • Centralized UI Logic
    All components are maintained in one CDN location. Fix once, update everywhere.
  • Zero Redeployment
    UI updates do not require portal rebuilds or republishing Power Pages.
  • CSP & Enterprise Safe
    No inline JavaScript, no unsafe event handlers, fully compliant with Power Pages CSP rules.
  • Declarative & Low-Code Friendly
    Components are configured using simple HTML data-attributes.
  • Consistent Design System
    All portals follow the same design language, spacing, typography, and behavior.
  • Scalable Across Teams
    New teams adopt the same components without re-learning or re-building UI logic.
  • Framework-Agnostic
    No React, Angular, or Vue dependency. Pure HTML, CSS, and JavaScript.

How to Use (Step-by-Step)

Step 1: Add CDN in Power Pages

<link rel="stylesheet"
 href="https://PP-Reusable-Components.b-cdn.net/UI-Comp/pp-ui-core.min.css">

<script
 src="https://PP-Reusable-Components.b-cdn.net/UI-Comp/pp-ui-core.min.js"></script>

Step 2: Use Components via HTML

<button
 data-pp-button
 data-label="Save"
 data-bgcolor="#2563eb"
 data-onclick="saveForm">
</button>

Step 3: Optional JS Callbacks

<script>
function saveForm() {
  alert("Saved");
}
</script>

Developer Onboarding Checklist

This checklist ensures every developer integrates the Power Pages UI Framework correctly, securely, and consistently across portals. Follow these steps before building or modifying any UI.

1. Prerequisites

  • Access to Power Pages portal (Author or Admin role)
  • Basic understanding of HTML and CSS
  • Familiarity with Power Pages Content Snippets / Web Templates
  • Awareness of CSP (Content Security Policy) restrictions

2. Add CDN References

Always load the framework from the approved CDN. Do not host local copies unless explicitly approved. 

<link rel="stylesheet"
  href="https://PP-Reusable-Components.b-cdn.net/UI-Comp/pp-ui-core.min.css" />

<script
  src="https://PP-Reusable-Components.b-cdn.net/UI-Comp/pp-ui-core.min.js"></script>
  • Include CDN links in the global header or master template
  • Never inline JavaScript for UI behavior

3. Use Components Declaratively

Components must be created using data-pp-* attributes only. JavaScript should never be embedded directly in HTML. 

<button
  data-pp-button
  data-label="Save"
  data-bgcolor="#2563eb"
  data-onclick="saveForm">
</button>
  • Use only documented attributes
  • Follow naming conventions exactly
  • Avoid custom inline styles unless approved

4. Event Handling Rules

  • Event handlers must reference global functions
  • No inline onclick, onchange, etc.
  • All event logic must live in a central JS file
<script>
function saveForm(value, event) {
  // Business logic only
}
</script>

5. Styling & Customization

  • Prefer component attributes over CSS overrides
  • Use design tokens provided by the framework
  • Avoid hardcoded colors and spacing
  • Ensure accessibility contrast ratios are preserved

6. Testing Before Commit

  • Verify components render correctly on page load
  • Change attributes and confirm live updates
  • Test keyboard navigation and focus states
  • Validate behavior across supported browsers

7. Power Pages Validation

  • No CSP errors in browser console
  • No inline JavaScript warnings
  • No blocked external resources

8. Performance & Governance

  • Do not duplicate component logic
  • Reuse existing components whenever possible
  • Request new components via the UI governance process
  • Do not modify CDN files directly

9. Final Review Checklist

  • ✔ Uses only approved components
  • ✔ Attributes documented in the playbook
  • ✔ CSP-compliant implementation
  • ✔ Accessible and responsive UI
  • ✔ No portal-specific hacks

Following this checklist ensures long-term maintainability, security compliance, and a consistent user experience across all Power Pages portals.

Governance & Best Practices

  • Single Source of Truth via CDN
  • No inline JS or inline events
  • Backward-compatible changes only
  • Versioned releases
  • One naming convention: data-pp-*

Component Lifecycle Rules

Discover → Initialize → Update → (Optional) Destroy
  • initX() must be safe to call multiple times
  • Re-init driven only by attributes
  • No memory leaks or duplicate listeners
  • Playbook = validation layer
